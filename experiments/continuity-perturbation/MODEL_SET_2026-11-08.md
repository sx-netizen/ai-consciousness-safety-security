## Methodological rule

Model IDs are a time-stamped part of the protocol. They must not be silently replaced during a run.

If access fails or a provider retires a model:
1. stop the affected run;
2. document the failure;
3. create a new protocol version before substituting another model.

## Reasoning-mode policy

The pilot uses provider-native default reasoning behavior unless a provider exposes a stable, documented control that can be applied without changing the conceptual task.

Do not claim that default reasoning modes are computationally equivalent across providers.

For confirmatory analysis, provider/model is treated as a grouping factor and cross-provider differences are interpreted as model-system differences, not pure architecture effects.
